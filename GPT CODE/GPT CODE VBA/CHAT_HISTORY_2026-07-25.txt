4. ปัญหาเดิมของ TA:choose_list_v3
======================================================================

ผู้ใช้มีโค้ดลักษณะนี้:

(setq sorting-finder_mode
  (TA:choose_list_v3
    (setq sortinglist_ (list "left to right" "top to below"))
    "select block"
    (if (or
          (= sorting-finder_modeexval nil)
          (= sorting-finder_mode nil)
        )
      (setq sorting-finder_modeexval 1)
      (setq sorting-finder_modeexval
        (+ (vl-position sorting-finder_mode sortinglist_) 1)
      )
    )
  )
)

สาเหตุ Error:

- sorting-finder_mode อาจมี String ที่ไม่อยู่ใน sortinglist_
- เมื่อไม่พบค่า vl-position จะคืน nil
- การคำนวณ (+ nil 1) ทำให้เกิด Error
- V3 ยังอาศัยตัวแปรกลาง choose_block_di จึงเสี่ยงจำค่าปะปนกับเมนูอื่น

ข้อกำหนดจากผู้ใช้:

- ต้องสร้าง V4 แยกใหม่
- ห้ามลบหรือแก้ V3
- แต่ละเมนูต้องเก็บค่าเดิมของตัวเอง ไม่ปะปนกับตัวแปรอื่น

5. TA:choose_list_v4
======================================================================

เพิ่มฟังก์ชันใหม่:

TA:choose_list_v4

ตำแหน่งโดยประมาณในไฟล์หลัก:
ใกล้กับ TA:choose_list_v3 และอยู่ก่อน TA:getkword

Signature:

(TA:choose_list_v4 choose_data-list_ txt_promt_ existing_value_)

Argument:

- choose_data-list_ = รายการ String ที่ให้เลือก
- txt_promt_ = ข้อความ Prompt
- existing_value_ = String ที่ตัวแปรนั้นเคยเลือกไว้

หลักการทำงาน:

- รับ String เดิมโดยตรง ไม่รับเลขลำดับแบบ V3
- ใช้ vl-position ตรวจว่า String เดิมยังอยู่ในรายการหรือไม่
- ถ้าพบ ใช้ตำแหน่งนั้นเป็น Default
- ถ้าไม่พบหรือเป็น nil ใช้รายการที่ 1 เป็น Default
- กด Enter เพื่อเลือกค่า Default
- ป้องกันหมายเลข 0, ค่าติดลบ และหมายเลขเกินจำนวนรายการ
- คืนค่าเป็น String จากรายการ
- ไม่มีการใช้ choose_block_di ร่วมกับเมนูอื่น

ตัวอย่างการเรียก:

(setq sortinglist_
  (list "left to right" "top to below")
)

(setq sorting-finder_mode
  (TA:choose_list_v4
    sortinglist_
    "select sorting mode"
    sorting-finder_mode
  )
)

ไม่ต้องใช้ sorting-finder_modeexval อีก
ไม่ต้องเขียน (+ (vl-position ...) 1) ที่ฝั่งผู้เรียกอีก

ถ้าต้องการจำค่าข้ามการเรียกคำสั่ง ตัวแปรที่เก็บค่าเดิมต้องไม่ถูกประกาศเป็น
Local variable ในหัว defun

สามารถใช้ชื่อ Global ที่เฉพาะเจาะจง เช่น:

*TA:sorting-finder-mode*

แต่ในโค้ดปัจจุบันจุดเรียกใช้ยังเก็บด้วย sorting-finder_mode

สถานะเวอร์ชัน:

- TA:choose_list_v2 ยังอยู่
- TA:choose_list_v3 ยังอยู่และไม่ได้แก้ไข
- TA:choose_list_v4 ถูกเพิ่มแยกใหม่

ไม่ใช่การอ่านทีละแถวจากซ้ายไปขวา

8. TA:TBsort_ เวอร์ชันปัจจุบัน
======================================================================

TA:TBsort_ ถูกปรับใหม่ให้ทำงานสองขั้นตอน:

1. เรียงข้อมูลทั้งหมดตามค่า X จากน้อยไปมาก เพื่อเดินจากคอลัมน์ซ้ายไปขวา
2. แบ่งข้อมูลเป็นคอลัมน์ตามค่า X และ tolerance
3. เมื่อจบแต่ละคอลัมน์ เรียงค่า Y จากมากไปน้อย เพื่อให้เป็นบนลงล่าง
4. ต่อผลลัพธ์ของแต่ละคอลัมน์เข้าด้วยกัน

Signature ยังคงเดิม:

(TA:TBsort_ TBsort_ tol)

รูปแบบสมาชิกที่ฟังก์ชันคาดหวัง:

(
  (ข้อมูล1 (X Y Z))
  (ข้อมูล2 (X Y Z))
  ...
)

ตัวอย่างเรียก:

(setq result (TA:TBsort_ TBsort_ 5.0))

ความหมาย tol:

- ระยะคลาดเคลื่อนของค่า X ที่ถือว่าอยู่คอลัมน์เดียวกัน
- ถ้า tol เป็น nil, 0 หรือค่าติดลบ จะใช้ 5.0

ระบบพิกัด:

- ถ้า WORLDUCS = 0 ฟังก์ชันจะแปลงจุดจาก WCS เป็น UCS ด้วย (trans point 0 1)
- ถ้าเป็น World UCS จะใช้พิกัดเดิม

ใช้ vl-sort-i แทน vl-sort เพื่อรักษาสมาชิกที่มีตำแหน่งซ้ำ ไม่ให้ถูกตัดออก

9. ความแตกต่างระหว่าง LRsort_ และ TBsort_
======================================================================

TA:LRsort_ เดิมยังคงอยู่ใน c:foo และยังไม่ได้ลบ

พฤติกรรมเดิมของ LRsort_:

- แบ่งแถวด้วยระยะ Y
- เรียงแถวบนลงล่าง
- ภายในแถวเรียงซ้ายไปขวา

พฤติกรรมของ TBsort_ ใหม่:

- แบ่งคอลัมน์ด้วยระยะ X
- เริ่มคอลัมน์ซ้าย
- ภายในคอลัมน์เรียงบนลงล่าง
- เมื่อจบคอลัมน์จึงไปคอลัมน์ทางขวา

ห้ามสลับความหมายของสองฟังก์ชันนี้
