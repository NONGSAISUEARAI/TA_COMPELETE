9. สาเหตุที่ข้อมูลตั้งแต่ Q36 รวมไม่ใกล้ 6050
======================================================================

พบสาเหตุหลัก 3 จุด:

9.1 จำกัดจำนวนชิ้นสูงสุดไว้ 8 ชิ้น

ก่อนแก้ โค้ดมี:

Const MAX_ITEMS_PER_STOCK As Long = 8

ตั้งแต่ Q36 หรือ Group 28 เป็นต้นไป ชิ้นยาวส่วนใหญ่ถูกใช้ไปแล้ว
เหลือชิ้นเล็กประมาณ 123 ถึง 154 แต่ระบบเลือกได้เพียง 8 ชิ้น

ตัวอย่าง Group 28:

= RawSum 4076

Allowance = 8 x 5 = 40
Used = 4116

จึงไม่มีทางเข้าใกล้ Stock 6050 ด้วยข้อจำกัด 8 ชิ้น

9.2 สูตร Gap เดิมคิดจาก RawSum

สูตรเดิม:

ทำให้ Allowance ถูกนับใน Used แต่ไม่ถูกหักจาก Gap

9.3 Allowed Waste ตั้งไว้ 6050

เมื่อ Stock = 6050 และ Allowed Waste = 6050
หมายความว่า Combination ที่เหลือ Gap มากเกือบทั้งเส้นก็ยังผ่านเงื่อนไข

แต่ยังถือว่าผ่าน เพราะ 4831 <= 6050

10. ความหมายของ MaxSearchNodes
======================================================================

MaxSearchNodes ไม่ใช่จำนวนชิ้นสูงสุดต่อ Stock

มันคือจำนวนเส้นทางหรือ Combination สูงสุดที่ Recursive Search
อนุญาตให้ทดลองต่อ Stock หนึ่งเส้น

ตัวอย่าง:
MaxSearchNodes = 5000

หมายถึงแต่ละ Stock ทดลองค้นหาไม่เกิน 5,000 nodes

ถ้ามี 65 Stock:
จำนวนสูงสุดโดยประมาณ = 65 x 5,000 = 325,000 nodes

ผลของค่า:
- ค่าน้อย = เร็ว แต่อาจพลาด Combination ที่ดีกว่า
- ค่าสูง = มีโอกาสพบชุดดีกว่า แต่ Excel คำนวณนาน
- ถ้า Greedy พบชุดที่ดีแล้ว อาจไม่ใช้ครบ Search Limit

คำแนะนำเบื้องต้นเมื่อ MaxItemsPerStock สูง:
- เริ่ม MaxSearchNodes ที่ 5,000
- ถ้าผลยังไม่ดี ค่อยเพิ่มเป็น 10,000
- ไม่ควรเริ่มที่ 50,000 ทันทีสำหรับ MaxItemsPerStock = 40

11. เพิ่ม Argument MaxItemsPerStock ใน PACK_MULTI_v3_1
======================================================================

ผู้ใช้กำหนดให้เพิ่ม Argument จำนวนชิ้นสูงสุดต่อ Stock ก่อน Allowance

Signature ใหม่:

=PACK_MULTI_v3_1(
    ValueRange,
    QtyRange,
    targetRange,
    TargetQtyRange,
    TargetWasteRange,
    [MaxItemsPerStock],
    [Allowance],
    [MaxSearchNodes]
)

ตัวอย่าง:

=PACK_MULTI_v3_1(K8:K85,L8:L85,M8:M10,N8:N10,O8:O10,8,5,5000)

ความหมาย:
- 8 = จำนวนชิ้นสูงสุดต่อ Stock
- 5 = Allowance หรือระยะใบตัดต่อชิ้น
- 5000 = Search Limit ต่อ Stock

ค่าเริ่มต้นเมื่อไม่ใส่ Optional Arguments:
- MaxItemsPerStock = 8
- Allowance = 5
- MaxSearchNodes = 50000

ข้อจำกัด:
- MaxItemsPerStock ต้องอยู่ระหว่าง 1 ถึง 40
- ถ้าน้อยกว่า 1 หรือมากกว่า 40 คืน #VALUE!
- จำกัด 40 ให้ตรงกับ Output Item1 ถึง Item40

ข้อควรระวัง:
- การเพิ่มจาก 8 เป็น 40 ทำให้ Combination เพิ่มขึ้นมาก
- Excel อาจใช้เวลาคำนวณนาน
- MaxSearchNodes ช่วยหยุดการค้นหาไม่ให้ยาวไม่สิ้นสุด

12. แก้ Gap ให้คำนวณจาก Used
======================================================================

ผู้ใช้สั่งให้ Gap คำนวณจาก Used แทน RawSum

สูตรเดิม:

Gap = Stock - RawSum

สูตรใหม่:

Used = RawSum + (Count x Allowance)
Gap = Stock - Used

ตัวอย่าง:

Stock = 6050
RawSum = 6030
Count = 4
Allowance = 5

Used = 6030 + (4 x 5)
Used = 6050

Gap = 6050 - 6050
Gap = 0

ปรับครบใน:
- Greedy Search
- Recursive Search
- เงื่อนไข Allowed Waste
- คอลัมน์ Gap
- คอลัมน์ Gap %
- เงื่อนไขหยุดค้นหาเมื่อ Gap เท่ากับ 0

PACK_SUMMARY_v3_1 ไม่ต้องแก้จากประเด็นนี้ เพราะ Summary อ่านค่า Gap
ที่ PACK_MULTI ส่งออกมาอยู่แล้ว

14. แนวทางย้าย VBA ไปเป็น .xll
======================================================================

ข้อสรุป:
- VBA ไม่สามารถกด Convert เป็น .xll ได้โดยตรง
- ต้องย้าย Logic ไป C#, VB.NET หรือ C/C++
- แนวทางที่เหมาะกับโปรเจกต์นี้คือ C# + Excel-DNA

ขั้นตอน:
1. สร้าง C# Class Library
2. เพิ่ม ExcelDna.AddIn
3. เพิ่ม ExcelDna.IntelliSense หากต้องการคำแนะนำ Argument
4. แปลง VBA Logic เป็น C#
5. Build เป็น Packed .xll
6. แจกเฉพาะ .xll

รายการที่ต้องแปลง:
- Range เป็น object[,] หรือ ExcelReference
- Collection เป็น List<T>
- Scripting.Dictionary เป็น Dictionary<TKey,TValue>
- Variant Array เป็น object[,]
- CVErr เป็น ExcelError
- Recursive Search เป็น C# recursion หรือ Dynamic Programming

ข้อดี:
- ผู้ใช้แก้ผ่าน VBA Editor ไม่ได้
- เร็วกว่า VBA สำหรับ Packing Search
- รองรับ Formula IntelliSense
- แจกเป็นไฟล์เดียวได้

ข้อจำกัด:
- .NET Assembly ยังสามารถถูก Decompile ได้
- ถ้าต้องการป้องกันมากขึ้น ต้องใช้ Obfuscation, Code Signing หรือ Native C++
