# ใบขอราคา HTML จากฟอร์มกลาง

ใช้ฟอร์มกลางสำหรับสร้างใบขอราคาใหม่หรือแก้ข้อมูลในไฟล์งานที่ผู้ใช้ระบุ ฟอร์มมีตัวอักษรไทย เส้นตารางเวกเตอร์ ตารางรหัสวัสดุ ปุ่มเพิ่มหน้า บันทึก HTML ดาวน์โหลด PDF โดยตรง และส่งออก Excel ลงฟอร์มต้นแบบ

## ต้นแบบ

- ฟอร์มกลางของโครงการ: `C:/TA/TA_COMPELETE/GPT CODE/GPT CODE - ใบทำราคา/ฟอร์มกลาง/BU2-DE-26xxx-MASTER.html`
- สำเนาที่มากับสกิล: [assets/BU2-DE-26xxx-MASTER.html](assets/BU2-DE-26xxx-MASTER.html) ใช้เมื่อเข้าถึงฟอร์มกลางไม่ได้
- ฟอร์มกลางเริ่มว่างหนึ่งหน้า ไม่มีรายการ โครงการ ผู้ขอราคา หรือวันที่จากงานเก่า
- เซฟงานเป็นไฟล์ใหม่เสมอ อย่าเขียนข้อมูลโครงการทับต้นแบบ การแก้ต้นแบบทำเฉพาะเมื่อผู้ใช้ขอแก้ฟอร์มกลาง

## เตรียมข้อมูล

อ่านแหล่งข้อมูลและคำสั่งปัจจุบันของผู้ใช้ก่อน ใช้เฉพาะรายการที่ผู้ใช้ยืนยันสำหรับงานนั้น ตัวอย่าง ภาพอ้างอิง และเอกสารเก่าไม่ใช่รายการสั่งซื้อโดยอัตโนมัติ

- นับรายการตามชิ้นงาน/ขนาด/สีที่ต้องแยกสั่ง รหัสสีเดียวกันหลายสถานีรวมได้เมื่อเป็นชิ้นงานเดียวกันและผู้ใช้อนุญาต ส่วนแถวซ้ำที่ผู้ใช้ยืนยันให้แยกต้องคงแยก
- จำนวนไม่ทราบให้เว้นว่างแล้วแจ้ง ไม่แทนด้วย 0 หรือยืมจำนวนจากตัวอย่าง
- ชื่อวัสดุอ่านจาก `model.materials[materialCode]` ตรวจรหัสก่อนลงข้อมูล ไม่พิมพ์ชื่อที่ขัดกับรหัส
- หมายเหตุใช้รหัสอ้างอิงที่ยืนยัน เช่น PC ห้ามเติม PP สถานี Drawing หรือหมายเหตุอื่นเอง
- แยกช่องสีมาตรฐาน `cc/sp/pc/acp/otherCoat` จากสีพิเศษ `specialColor/paintType/brand` ตามข้อมูลต้นทาง ไม่เดายี่ห้อหรือชนิดสีจากรหัสที่ไม่รู้จัก
- ชื่อชิ้นงาน โครงการ JO วันที่ และเลขใบขอเป็นข้อมูลของแต่ละงาน ไม่ใช้ค่า 26106 หรือ PJ25-031 เป็นค่าเริ่มต้น

## สร้างไฟล์งาน

อ่าน [references/data-schema.md](references/data-schema.md) เมื่อต้องเตรียม JSON สำหรับตัวช่วย แล้วใช้ [scripts/create_rfq.py](scripts/create_rfq.py) ซึ่งใช้ Python standard library:

```text
python <skill-dir>/scripts/create_rfq.py --template <master.html> --input <data.json> --output <new-document.html>
```

ถ้าไม่ส่ง `--template` ตัวช่วยใช้สำเนาใน `assets` โดยอัตโนมัติ ตัวช่วยป้องกันการเขียนทับไฟล์ที่มีอยู่และการเขียนทับ master

ชื่อไฟล์อ้างอิง: `BU2-DE-26[รหัส]_โครงการ [ชื่อโครงการ] [ชื่อวัสดุ]` ใช้ฐานชื่อเดียวกันทั้ง HTML, PDF และ XLSX ผู้ใช้แก้ชื่อเองได้ในช่องชื่อไฟล์

ตารางหลักรองรับ 20 รายการต่อหน้า ตัวช่วยแบ่งหน้าและเรียงลำดับให้อัตโนมัติ หากมีหน้าว่างเพิ่มเติมต้องรักษาจำนวนหน้าตามที่ผู้ใช้ขอ

ถ้าแก้ไฟล์งานเดิม ให้แก้ `template-model` และค่าหัวเอกสารให้สอดคล้องกัน โดยเฉพาะ `current`, `document`, `headers`, `pageCount`, `pageChecks`, `fileNaming` อย่านำ `original` หรือ `new` จากไฟล์ตัวอย่างมาเติมรายการซ้ำ

## คงรูปแบบและการส่งออก

- รักษาหน้ากระดาษ 792 × 612 จุด (Letter แนวนอน) ตำแหน่ง `.form-lines`, `model.edges`, `rowTops`, `secondaryRowTops`, ฟอนต์ฝัง และกล่องติ๊กตามต้นแบบ
- รักษาสคริปต์ `pdf-export-library`, `pdf-fontkit-library`, ฟังก์ชันสร้าง PDF และ license notices ไว้ใน HTML เพื่อให้ใช้ไฟล์เดียวได้โดยไม่พึ่ง CDN หรือเซิร์ฟเวอร์
- ปุ่ม **ดาวน์โหลด PDF** สร้างไฟล์จากข้อมูลปัจจุบันบนทุกหน้าโดยตรง ใช้ฟอนต์ฝังและตำแหน่ง glyph ภาษาไทย พร้อม ActualText สำหรับค้นหา/คัดลอก ห้ามแทนด้วยภาพจับหน้าจอหรือ `window.print()`
- ปุ่ม **พิมพ์** แยกไว้สำหรับหน้าต่างพิมพ์ตามปกติ ช่องตั้งชื่อและเครื่องมือไม่ลงบนเอกสาร
- ปุ่ม **ดาวน์โหลด Excel** ใช้ข้อมูลที่แก้บนหน้าปัจจุบันทั้งหมด สร้างหนึ่งชีตต่อหน้า โดยใช้ชีตแรกของ Excel ที่ผู้ใช้ให้เป็นต้นแบบ รักษาสูตร ช่องติ๊ก โลโก้ และหน้าพิมพ์ของ Excel อ่าน [references/excel-export.md](references/excel-export.md) เมื่อแก้กลไกส่งออกหรือเปลี่ยนต้นแบบ Excel
- บันทึก HTML ต้องคงข้อมูลที่แก้ ช่องติ๊ก จำนวนหน้า ตัวสร้าง PDF และต้นแบบ/ตัวสร้าง Excel ที่ฝังไว้ เพื่อให้เปิดไฟล์ที่บันทึกแล้วใช้งานต่อได้

## ตรวจและส่งงาน

ตรวจจำนวนรายการ ผลรวม จำนวนหน้า รหัสวัสดุ/ชื่อวัสดุ และชื่อไฟล์เทียบแหล่งข้อมูล เปิด HTML ตรวจตารางและทดสอบการส่งออกที่ขอ ตรวจ PDF ที่ได้จริงทั้งฟอนต์ไทยและการจัดหน้า ส่วน Excel ตรวจข้อมูล สูตร ช่องติ๊กทุกชีต และหน้าพิมพ์ ถ้ามีการแก้กลไกส่งออก ให้ทดสอบข้อมูลที่แก้ ช่องติ๊ก หน้าเพิ่ม และการคงตัวส่งออกใน HTML ที่บันทึกด้วย

ส่งลิงก์ไฟล์งานและสรุปจำนวนรายการ/ชิ้น/หน้า เก็บต้นแบบไว้ตามเดิม การสร้างใบขอราคาไม่ได้อนุญาตให้เผยแพร่เว็บหรือส่งเอกสารให้ผู้อื่น
