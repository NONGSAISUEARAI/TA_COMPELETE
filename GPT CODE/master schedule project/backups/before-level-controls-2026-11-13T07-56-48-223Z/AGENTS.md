# แนวทางทำงานกับ Master Schedule

## ไฟล์และข้อมูลอ้างอิง

- ไฟล์ใช้งานหลักคือ `Master_Schedule.html` เป็น HTML ไฟล์เดียว รวมหน้าตา โปรแกรม และข้อมูลไว้ด้วยกัน ไม่ต้องติดตั้งแพ็กเกจเพื่อใช้งาน
- อ่านข้อมูลปัจจุบันจาก `<script id="schedule-data" type="application/json">` ในไฟล์จริงก่อนแก้ทุกครั้ง และอ่าน `README.md` เพื่อดูรายการงานล่าสุด
- สำเนาใน `backups/` เป็นข้อมูลเก่าเพื่อกู้คืน ไม่ใช่ไฟล์ใช้งานหลัก อย่านำกลับมาแทนไฟล์ปัจจุบันโดยอัตโนมัติ
- ไม่ถือว่าฉบับร่างในเบราว์เซอร์ถูกบันทึกลง HTML แล้ว หากหน้าเก่ายังเปิดค้างและมีข้อมูลเพิ่ม ให้บันทึกสำเนาคนละชื่อเพื่อผสานข้อมูลกับโค้ดล่าสุด ไม่บันทึกหน้าเก่าทับไฟล์ที่เพิ่งแก้โค้ด

## โครงสร้างที่ผู้ใช้กำหนด

- ล่าสุด Rev04 วันที่ 13 พฤศจิกายน 2026 รองรับ LV4 · Activity: LV1 PJ + Project Works / LV2 Product + Group Drawing / LV3 Description / LV4 Activity ไม่แยก Group Drawing กับ Product เป็นคนละระดับ ใช้ databaseModel เดิม project-product-work-v1; databaseLevel() คำนวณระดับจาก parentId
- ข้อมูลใช้งานจริงล่าสุดตอนปรับ UI มี 3 หมวดหลัก/52 แถวย่อย รวม 55 แถว มี 10 Product/33 Description/0 Activity ที่บันทึกจริง อ่าน HTML จริงก่อนแก้ทุกครั้ง ไม่ใช้จำนวนคงที่ทับข้อมูลใหม่
- LV1 อยู่ใน groups; LV2 เป็น task nodeType section ใต้ group; LV3 และ LV4 เป็น nodeType task แยกระดับด้วย parentId ทั้ง Description/Activity ใช้ name เก็บชื่อ เมื่อ Description มีลูกจะเป็นหัวข้อสรุปโดยไม่เปลี่ยน id ไม่ต้องเปลี่ยน nodeType เป็น section จึงยังกลับเป็นงานได้เมื่อไม่มี Activity
- Activity มี id, สี, fileCatalog และ Plan/Actual ของตัวเอง ห้ามเพิ่มต่อจาก LV4 เลือกแม่ได้เฉพาะ Description ระดับ3และป้องกันวงจร/ข้ามหมวด legacy; ชื่อ Activity แยกจากฟิลด์ Action เดิม เมื่อย้าย Description หรือ Product ให้พาลูกไปด้วยและปรับพื้นที่ที่สืบทอดตาม Product
- เพิ่ม Activity แรกต้องเก็บวันเดิมของ Description เป็นวันกำหนดเองถ้ามี ไม่คัดลอกวัน/owner/% ให้ลูกใหม่ หัวข้อแม่สรุป%จากงานระดับสุดท้าย ไม่บวกซ้ำ วันที่แม่แก้ manual หรือกลับใช้วันลูกได้แยก Plan/Actual และไม่เปลี่ยนวันลูก
- กล่องเพิ่ม/แก้ไขใช้ระดับ product/work/activity เปลี่ยน label Description/Activity ตามระดับ แสดง Description แม่อ่านอย่างเดียวสำหรับ LV4 ใช้ต้นไม้ค้นหาและ SVG เดิม + ย่อย บน LV3 เปิด Activity; LV4 ไม่มีปุ่มเพิ่มต่อ
- เก็บ JSON ใน schedule-data ตรงกับก่อนแก้ทุกค่า ไม่มี Activity ตัวอย่างในข้อมูลจริง สำเนาก่อนแก้รวมชุดตรวจ: backups/before-LV4-Activity-2026-11-13T04-34-38-441Z/ ไม่อ่าน Z: หรือคืน backup เก่าอัตโนมัติ
- หมวด MRT เอกสารเก่า C02–C10, fileCatalog 6 โฟลเดอร์และไฟล์เลือก 14 ไฟล์คงเดิม รักษาชื่อ/สะกด/id ที่บันทึกล่าสุด ไม่กู้ชั้น PP17–PP20 หรือชื่อ MOCKUP เดิมทับผู้ใช้

## กติกาที่ต้องรักษา

- หน้าจอใช้ main เต็มความกว้าง (max-width:none; width:100%; margin:0; padding แนวนอน 0) ไม่คืนกรอบจำกัด 1680px หรือขอบว่างซ้าย–ขวา ใช้เฉพาะ @media screen และคงการพิมพ์เดิม ปุ่มเต็มจอยังเป็นอีกมุมมองหนึ่ง


- UI ป้ายไฟล์ทุกระดับชิดขอบขวาของ Description ไม่วางตำแหน่งตามความยาวชื่อ เปิดรายการแล้วใช้เต็มแถวได้ คอลัมน์ Description ลากปรับขอบหัวตารางได้ทั้ง Viewer/Editor (keyboard/ยกเลิก/คืนค่าเดิม) จำค่าผ่าน localStorage view preference เท่านั้น ไม่แก้ state/dirty/draft/Auto-save ไม่วาดตารางใหม่ระหว่างลาก และรักษา SVG tree/details/ลิงก์เดิม บนจอเล็กให้เลื่อนถึงขอบคอลัมน์ได้


- ย้ายลำดับโดยคลิกเลข WBS ต้นทางแล้วคลิก WBS ปลายทางใน Editor เลือกวางก่อน/หลังและยืนยัน ไม่มีปุ่ม ↑/↓ แยกทุกแถว ต้นทางและปลายทางที่ใช้ได้แสดงสถานะชัดเจน รองรับ Enter/Space/Esc คลิกต้นทางซ้ำหรือยกเลิกไม่แก้ข้อมูล หมวดหลักย้ายใน groups งานย่อยย้ายภายใน groupId/parentId เดียวกันตามลำดับทั้งหมดรวมรายการที่ถูกกรอง ย้ายหัวข้อพร้อมลูกทุกระดับและจัด tasks เป็นลำดับต้นไม้ ไม่แก้ id/parentId/groupId หรือข้อมูลรายการ ตรวจสิทธิ์และความสัมพันธ์ซ้ำก่อนวาง อัปเดต WBS/เส้นต้นไม้ คงลำดับในฉบับร่าง Auto-save และ snapshot HTML และยกเลิกสถานะเลือกเมื่อกลับ Viewer
- โปรแกรมปัจจุบันเป็น Rev04 ตามคำขอวันที่ 9 พฤศจิกายน 2026 เพิ่มช่อง pjCode/projectWorks/drawingGroup/product/currentInfo/unit/quantity/workStatus/action/approvedDate/remark ตาม Excel Programm Database!A4:P4 โดยเก็บรายการงาน/ค่าเดิม ไม่สร้างลำดับงานจาก Excel แทน Tree ช่อง Description/Man/Duration ใช้ name/owner/จำนวนวันเดิม Quantity ว่างใช้ null แยกจาก 0 ที่ผู้ใช้ยืนยัน workStatus ไม่แทนสถานะตามวันที่ที่ระบบคำนวณ
- Plan ใช้ start/end และ dateMode/planStart/planEnd เดิม Actual ใช้ actualStart/actualEnd และ actualDateMode manual/auto แยกชุด แก้ได้ทั้งงานย่อย หัวข้อแม่ และหมวดหลัก มีปุ่มกลับใช้วันที่ลูกแยก Plan/Actual ไม่แก้วันที่ลูก และไม่อนุมาน progress จาก Actual หรือวันที่จริงจาก progress วันที่จริงไม่ครบแสดงวันที่ข้างที่ทราบและจุดบน Gantt ไม่สร้างอีกข้าง สรุป Actual จากลูกแยกแต่ละข้างเมื่อทุกงานระดับสุดท้ายระบุวันที่ข้างนั้นครบ
- Gantt แยก Plan เฉดสีด้านบนและ Actual สีเต็มด้านล่าง คงสีประจำหัวข้อและสถานะเลยกำหนดจากกติกาเดิม ขอบเขตปฏิทินรวม Plan/Actual ทั้งงานและหัวข้อแม่ วันอาทิตย์ยังเลื่อนไปจันทร์และแถบเว้นอาทิตย์ ตารางเปิดข้อมูลแบบเพิ่มเติมได้ด้วย checkbox ข้อมูลแบบ (Excel) โดยไม่เปลี่ยนข้อมูล/Auto-save รักษา treeGuides เดิมทุกประการ
- รูปแบบวันที่ในตารางเป็นคอลัมน์ Start และ End แต่ละงานมี Plan แถวบน/Actual แถวล่าง วันที่ start/actualStart อยู่ใต้ Start และ end/actualEnd อยู่ใต้ End ข้อมูลวันที่และฟอร์มกรอกยังแยกชุดเดิม ส่วนป้ายไฟล์ของโครงการฐานข้อมูลวางข้างชื่อใน db-title-line เปิดรายการแล้วขึ้นบรรทัดเต็มได้ ส่วนหมวดเอกสารเก่ายังคงระยะเยื้องเดิม ไม่เปลี่ยน treeGuides
- ตารางหลักเรียง WBS → PJ → Project Works → Group Drawing → Product → Description ตามภาพผู้ใช้ โดย 4 ช่องนี้ซ่อนเป็นค่าเริ่มต้นเมื่อเปิดหน้า และมีปุ่ม Hide/Unhide ซ่อนแสดงเป็นชุด แยกจากข้อมูลเพิ่มเติม ไม่แก้ state/dirty/Auto-save และไม่ลบค่า และฟอร์มงาน/หมวดหลักเรียงชุดเดียวกันก่อน Description ไม่เพิ่มฟิลด์ชื่อ Heading รักษาเส้น Tree ใน Description และยึดคอลัมน์ WBS/Description ด้วยคลาส semantic แทนตำแหน่ง nth-child ที่เปลี่ยนไป
- สำหรับหมวด legacy หัวข้อหลักแก้ช่อง “อยู่ใต้หัวข้อ” เพื่อเปลี่ยนเป็น section ใน tasks ได้เมื่อบันทึก ใช้ id เดิม เก็บ metadata/Plan/Actual/สี/ขอบเขตงาน/ไฟล์ครบ ลูกทุกระดับย้าย groupId ไปปลายทาง ลูกตรงเดิมเปลี่ยน parentId มาอยู่ใต้ section ที่สร้างจากหมวดเดิม แล้วเอาหมวดนั้นออกจาก groups หลังตรวจสอบครบเท่านั้น ป้องกันเลือกตัวเอง/ลูกตัวเอง วงจร เป้าหมายหาย และ id ซ้ำ ยกเลิกก่อนบันทึกไม่เปลี่ยนข้อมูล ใช้ต้นไม้ค้นหาและ treeGuides เดียวกับช่องเลือกแม่เดิม แสดง preview หลังบันทึก ยุบ–ขยายและ WBS ตามรหัสเดิม และเปิดเส้นทางปลายทางให้เห็น หน้าแก้ไขงานย่อยต้องเก็บ/แก้ note ขอบเขตงานเดิมได้
- สำหรับหมวด legacy งานย่อยแตกต่อได้หลายระดับ เช่น 1.1 → 1.1.1 → 1.1.1.1 และยุบ–ขยายได้ เลข WBS คำนวณจากลำดับ ไม่ใช่รหัสถาวร
- ใช้ Dark Mode บนหน้าจอทั้งหน้าหลัก ตาราง และหน้าต่างแก้ไข ส่วนการพิมพ์ใช้พื้นสว่าง
- เส้นต้นไม้ในตารางต้องต่อเนื่องตามระดับ หยุดที่ลูกตัวสุดท้าย และคำนวณตามแถวที่มองเห็นหลังกรองหรือยุบ–ขยาย
- เส้นต้นไม้ใช้ SVG ความหนามาตรฐาน 1px ร่วมกัน พร้อม `non-scaling-stroke` และ `crispEdges` ทั้งตารางและตัวเลือกหัวข้อแม่ อย่าใช้หลายวิธีวาดหรือเส้นต่างความหนาผสมกัน
- ช่อง “อยู่ใต้งาน” ใช้ตัวเลือกรูปต้นไม้ที่ค้นหาได้ แสดง WBS และชื่อเยื้องตามระดับ โดยยังเก็บค่าที่เลือกใน `f-parent`; ไม่ย้อนกลับไปใช้รายการแบนที่อ่านระดับยาก
- หน้าเพิ่ม/แก้ไขแสดงต้นไม้ตำแหน่งงาน และหน้าต่างยืนยันลบเป็น Dark Mode พร้อมเส้นทางรายการจริง ใช้ `treeGuides` เส้น 1px เดียวกัน เปลี่ยนข้อมูลเมื่อยืนยันลบเท่านั้น ตรวจสิทธิ์และงานลูกซ้ำก่อนลบ ยกเลิกแล้วคงข้อมูลและหน้าแก้ไขไว้
- `groups` เก็บหมวดหลัก ส่วน `tasks` เชื่อมด้วย `groupId` และ `parentId`; รักษา `id` เดิมเมื่อแก้รายการ
- `nodeType: "section"` หมายถึงหัวข้อจัดกลุ่ม แม้ยังไม่มีลูกก็ไม่นับเป็นงานที่ใช้คำนวณความก้าวหน้า
- วันที่และ `progress` ที่ยังไม่ระบุใช้ `null`; ผู้รับผิดชอบที่ไม่ทราบใช้ข้อความว่าง แยก `null` ออกจากความก้าวหน้า 0% ที่ผู้ใช้ยืนยันแล้ว
- ความก้าวหน้าของหัวข้อแม่สรุปจากงานระดับสุดท้ายเท่านั้น และยอดรวมไม่นับซ้ำหัวข้อแม่ ความก้าวหน้าถ่วงน้ำหนักตามจำนวนวันทำงาน
- ช่องวันที่ของงานและหัวข้อแม่ต้องแก้ไขได้ใน Editor หัวข้อแม่เลือกกำหนดช่วงแผนเอง (`dateMode: "manual"`, `planStart`, `planEnd`) หรือกด “ใช้วันที่จากงานย่อย” เพื่อกลับไปสรุปอัตโนมัติได้ การกรอกแผนหัวข้อแม่ไม่เปลี่ยนวันที่ลูก และยังคงล็อกเฉพาะ % ผลงานที่สรุปจากลูก
- คงโหมดวันที่และวันแผนที่ผู้ใช้กำหนดหลังบันทึก แก้ข้อมูลอื่น หรือเปิดไฟล์ใหม่ และรวมช่วงวันแผนหัวข้อแม่ในขอบเขตปฏิทิน
- งานและหมวดหลักเลือกสีแถบ Gantt รายหัวข้อได้ในหน้าแก้ไข เก็บ `barColor` เป็น `null` สำหรับสีเริ่มต้น หรือรหัส `#rrggbb` ที่ผ่านการตรวจสอบ ไม่เปลี่ยนสีงานลูกโดยอัตโนมัติ รักษาสีหลังบันทึกและเปิด HTML ใหม่ พร้อมตัวอย่างสี สีสำเร็จรูป และปุ่มคืนสีเริ่มต้น
- สีช่วงแผนเป็นเฉดของสีที่เลือก ส่วนสีผลงานใช้สีเต็ม สถานะเลยกำหนดยังคำนวณตามข้อมูลเดิมแม้ผู้ใช้กำหนดสีแถบเอง
- หากไม่มีวันแผนที่ผู้ใช้กำหนดและวันที่ลูกยังไม่ครบ ให้แสดงรอข้อมูล วันและเปอร์เซ็นต์ที่ยังไม่ทราบต้องไม่สมมติขึ้น
- ปฏิทินแสดงจันทร์–อาทิตย์ แยกสีเสาร์และอาทิตย์ นับวันทำงานจันทร์–เสาร์ วันเริ่มหรือจบที่เลือกเป็นอาทิตย์เลื่อนไปจันทร์ แถบงานเว้นอาทิตย์
