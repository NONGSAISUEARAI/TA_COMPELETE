# ดูแล Master Schedule

ใช้กับ HTML ไฟล์เดียวของโปรเจกต์นี้ โดยรักษาข้อมูลที่ผู้ใช้บันทึกไว้ คุยภาษาไทยและอธิบายผลลัพธ์กระชับ

## ข้อตกลงล่าสุด — 10 พฤศจิกายน 2026

- ใช้ **CSV UTF-8 นำเข้าข้อมูล** ต่อไป ผู้ใช้ยืนยันไม่เปลี่ยนเป็นนำเข้า XLSX โดยตรง และไม่ใช้ VBA ในขั้นตอนทำข้อมูล เลือก Save As ชนิด CSV UTF-8 ใน Excel
- ข้อมูลหลักอยู่ใน JSON ภายใน HTML; CSV ใช้แลกเปลี่ยนข้อมูล; XLSX ใช้รายงานที่มีสี รูปแบบ สูตร และ Gantt CSV ไม่เก็บสูตรหรือรูปแบบตาราง
- สูตรและ Template ต้องรองรับ **Excel 2016–2024** ใช้ 2016 เป็นฐาน ไม่พึ่ง Microsoft 365 และไม่ใช้ `IFS`, `LET`, `UNIQUE`, `FILTER`, `XMATCH` หรือฟังก์ชันที่ 2016 ไม่มี ใช้สูตรรุ่นเก่าและคอลัมน์ช่วยได้ตามความจำเป็น
- แนวทางที่ตกลงจะพัฒนา: เก็บ `Drawing_Template.xlsx` ใน GitHub ให้ HTML โหลดสำเนา เติมข้อมูลลงตำแหน่งที่กำหนด แล้วส่งออกเป็น XLSX ใหม่ คงแม่แบบต้นฉบับไว้ ไม่จำเป็นต้องสร้าง CSV เป็นไฟล์กลางทุกครั้งที่ Export; สำหรับออฟไลน์ต้องมีแม่แบบฝังหรือให้เลือกจากเครื่อง
- **Template ล็อกโครงสร้างและตำแหน่งแถวทั้งหมด เพิ่มได้เฉพาะแนวนอน** ไม่ให้ผู้ใช้แทรก/ลบ/ย้ายแถวหรือเพิ่มงานแนวตั้งในแม่แบบ คอลัมน์ข้อมูลหลักต้องอยู่ตำแหน่งเดิม ส่วนขยายเพิ่มทางขวาตามข้อตกลงของรุ่นแม่แบบ หากรายการงานเปลี่ยนให้ทำใน HTML และเตรียมแม่แบบรุ่นที่รองรับ
- ผู้ใช้ต้องการ **WBS เป็นสูตรที่ล็อกไว้ใน Template** ผูกกับลำดับงานและคู่ Plan/Actual ที่เตรียมไว้ ไม่ใช้ WBS แทน Task ID สูตรตัวอย่างก่อนหน้าเป็นการหารือ ยังไม่มีสูตรสุดท้ายที่ยืนยันกับแม่แบบจริง โดยเฉพาะสูตร 365 และข้อสมมติเรื่องเพิ่มแถวถูกยกเลิกแล้ว

ส่วนนี้บันทึกข้อตกลงออกแบบ ไม่ได้แปลว่าเขียนโปรแกรมครบแล้ว HTML ปัจจุบันยังใช้ EXCEL_TEMPLATE ภายในไฟล์ และยังมีโค้ด/ปุ่ม VBA เก่าซึ่งเลิกใช้ในแนวทางใหม่ การอัปเดตเอกสารครั้งนี้ไม่ลบโค้ดหรือเปลี่ยนข้อมูล ดูตารางสถานะใน README.md ก่อนรายงานความสามารถที่มีจริง

## เริ่มจากไฟล์จริง

1. อ่าน [AGENTS.md](AGENTS.md) สำหรับกติกาของโปรเจกต์ และ [README.md](README.md) สำหรับวิธีใช้/รายการล่าสุด
2. อ่านและแปลง JSON จาก `<script id="schedule-data" type="application/json">` ใน [Master_Schedule.html](Master_Schedule.html) ก่อนแก้โปรแกรมหรือข้อมูลทุกครั้ง ตรวจรายการ, id, แม่–ลูก, วันที่ และ fileCatalog ที่จะได้รับผลกระทบ
3. ยึดข้อมูลจริงและคำสั่งล่าสุดของผู้ใช้เหนือจำนวนงานหรือตัวอย่างเก่า สำรอง HTML ใน `backups/` ด้วยชื่อไม่ซ้ำก่อนแก้โปรแกรมหรือข้อมูล ไม่ต้องสร้างสำเนา HTML หากแก้เฉพาะเอกสาร

ห้ามนำ backup, fixture หรือ Master_Schedule_REV01.html มาทับไฟล์หลักอัตโนมัติ หากต้องกู้ ให้เปรียบเทียบข้อมูลและผสานเฉพาะส่วนที่ยืนยันแล้ว ไม่อ่านไดรฟ์ Z: ตามข้อกำหนดปัจจุบัน

หากมีข้อมูลเพิ่มในหน้าเบราว์เซอร์เก่า ให้บันทึกแยกชื่อแล้วผสานกับโค้ดล่าสุด ฉบับร่างในเบราว์เซอร์ยังไม่ถือว่าลง HTML แล้ว อย่าบันทึกหน้าเก่าทับไฟล์ที่เพิ่งแก้

## โครงสร้างข้อมูลที่ต้องรักษา

| ระดับ | ข้อมูล | ที่เก็บ |
| --- | --- | --- |
| LV1 | PJ + Project Works | `groups[].pjCode`, `projectWorks`; `databaseModel: "project-product-work-v1"` |
| LV2 | Product + Group Drawing | `tasks[]` ที่เป็น `section`, `parentId: null`, ผูก `groupId` |
| LV3 | Description + PLAN/ACTUAL | `tasks[]` ที่เป็น `task`, `parentId` ชี้ LV2, Description อยู่ใน `name` |

- ใช้ `drawingFieldsFor()` รับข้อมูลโครงการและ Product จากหัวข้อแม่ ไม่คัดลอกค่าที่สืบทอดไปเก็บซ้ำในงานจนแก้ชื่อแม่แล้วลูกล้าสมัย
- งานเดียวมี id เดียวและวัน 2 ชุด ไม่สร้าง task แยกสำหรับ Plan กับ Actual รักษา id เมื่อแก้ชื่อ ย้าย หรือบันทึก WBS คำนวณจากลำดับและใช้แทน id ไม่ได้
- Plan ใช้ `start/end`; วันแผนหัวข้อแม่ใช้ `dateMode/planStart/planEnd` ส่วน Actual ใช้ `actualStart/actualEnd/actualDateMode` กำหนดเองได้แยกชุด ไม่แก้วันที่ลูกตามแม่โดยอัตโนมัติ
- ค่าไม่ทราบใช้ `null` สำหรับวัน/ผลงาน/ปริมาณ ผู้รับผิดชอบใช้ข้อความว่าง อย่าแทนด้วย 0 หรือสมมติวัน ไม่คำนวณ progress จาก Actual
- โครงการฐานข้อมูลใช้ 3 ระดับ ส่วนหมวดเอกสาร legacy ยังคงโครงสร้างเดิม อ่านรายชื่อปัจจุบันจาก JSON ไม่สร้างชั้น PP หรือคัดลอกรายการเก่ากลับเอง
- เก็บหมวด MRT เอกสารล่างสุดและ fileCatalog/selected เดิม เว้นแต่ผู้ใช้ขอแก้โดยตรง แก้เฉพาะ metadata ไม่ฝังเนื้อหาไฟล์หรือ session token ใน HTML

## เลือกแนวทางตามงาน

**แก้หน้าตาหรือฟอร์ม:** รักษา Dark Mode, เส้น SVG `treeGuides` 1px พร้อม `non-scaling-stroke`/`crispEdges`, การยุบ–ขยาย และวันที่ PLAN/ACTUAL คนละบรรทัด ป้ายไฟล์โครงการฐานข้อมูลอยู่ข้างชื่อ เริ่มซ่อน 4 คอลัมน์ข้อมูลโครงการ และเริ่ม Viewer เสมอ Editor ใช้รหัส `123123` กติกาวันทำงาน/ไฟล์/สี/การย้าย ดู AGENTS.md

**แก้รายการงาน:** คงลำดับที่บันทึกไว้และความสัมพันธ์ของงาน ไม่สร้าง id ใหม่ให้รายการเดิม ไม่ลบหัวข้อพร้อมลูกโดยเงียบ ๆ คำนวณสรุปจากงานระดับสุดท้ายและไม่นับ section ซ้ำ

**แก้ Export/Import:** ข้อมูลฐานข้อมูลส่งออกเฉพาะงาน LV3 เป็น 2 แถว Plan/Actual และเติม PJ, Project Works, Group Drawing, Product, Description ครบทุกแถว

- A:P ตามต้นแบบ, Q=WBS, R=Plan/Actual, S=Node Type, T=Task ID, U=Project ID, V=Product ID; XLSX ซ่อน S:V และปฏิทินเริ่ม W
- รักษา EXCEL_TEMPLATE และสี/ฟอนต์/format เดิม รวมสูตรวันทำงานและ Gantt เว้นอาทิตย์ CSV ไม่เก็บสีหรือ format; ใช้ XLSX เมื่อต้องการรูปแบบตาราง
- นำเข้าจับคู่ Task ID ก่อน หากไม่มีใช้ข้อมูล 5 ช่องที่ครบและไม่ซ้ำ ตรวจรหัสแม่และคู่ Plan/Actual ให้ตรงกัน แสดง preview ก่อนยืนยัน ไม่ล้างค่าว่างโดยปริยาย
- งานใหม่เว้น WBS/Task ID ได้ หากเพิ่มโครงการหรือ Product ใหม่ให้เว้นรหัสแม่ด้วย ให้โปรแกรมสร้าง id ภายใน ไม่ใช้ id จากภายนอกสร้างทับรายการเดิม
- กติกาเพิ่มงานข้างต้นเป็นพฤติกรรม CSV ทั่วไปที่มีอยู่เดิม ไม่ใช่การอนุญาตให้เพิ่มแถวใน Template แบบล็อกแถว รุ่นแม่แบบต้องกำหนดชุดงานที่ยอมรับอย่างชัดเจน
- VBA ในไฟล์เดิมเป็นส่วนเก่าที่ไม่ใช้ในกระบวนการใหม่ ไม่แนะนำให้ผู้ใช้ใช้หรือพัฒนา VBA ต่อเพื่อตอบโจทย์นี้ หากมีงานเลิกใช้โค้ดเก่าในภายหลัง ค่อยปรับปุ่ม/โค้ดฝัง/ชุดตรวจพร้อมกันโดยรักษาข้อมูลเดิม

## การตรวจสำหรับ Template แบบล็อกแถวที่ต้องพัฒนา

ตรวจไฟล์ทั้งชุดและแสดง preview ก่อนยืนยัน หากมีข้อผิดพลาดต้องยังไม่แก้ข้อมูลจริง ระบุแถว คอลัมน์ ค่าที่พบ ค่าหรือรูปแบบที่คาดหวัง และสาเหตุที่แก้ตามได้ ไม่เดาค่าแทนผู้ใช้

1. ตรวจรหัส/เวอร์ชันแม่แบบและชุดแถวที่กำหนด รวมจำนวน ตำแหน่ง และรหัสงานที่ควรมี รายละเอียดที่อยู่ของ metadata และรุ่นแม่แบบยังต้องกำหนดกับไฟล์จริง
2. ตรวจชื่อและตำแหน่งหัวคอลัมน์หลัก รวมแถวเริ่มข้อมูล ปฏิเสธหัวข้อที่ขาด สลับ หรือซ้ำ รับส่วนขยายแนวนอนเฉพาะที่มาตรฐานรุ่นนั้นระบุ ไม่ให้เลื่อนคอลัมน์หลัก
3. ตรวจข้อมูล 5 ช่องหลักให้ครบทุกแถว ชนิดข้อมูล วันที่จริง ปริมาณ และวันจบไม่ก่อนวันเริ่ม โดยรักษา null แยกจาก 0
4. ตรวจแต่ละ Task ID มี Plan หนึ่งแถวและ Actual หนึ่งแถว คู่ `Task ID + ประเภทแถว` ต้องไม่ซ้ำ เปรียบเทียบชุด ID ทั้งสองฝั่ง ไม่ใช้เพียงจำนวนรวม เพราะจำนวนเท่ากันแต่งานคนละตัวได้ วันที่ Actual ยังว่างได้
5. ตรวจข้อมูลโครงการ/Product/Description ของคู่ Plan–Actual และรหัสแม่ให้ตรงกัน ตรวจ WBS กับมาตรฐานโครงสร้างและชุดแถวที่เตรียมไว้ ไม่เชื่อเลขที่อ่านจาก CSV เพียงอย่างเดียว
6. ตรวจผลกระทบก่อนบันทึกว่าเพิ่ม/แก้งานใด ค่าเดิมเป็นอะไร ค่าที่จะนำเข้าเป็นอะไร เก็บสี ไฟล์แนบ และข้อมูลเดิมที่อยู่นอกขอบเขตนำเข้า

สูตร WBS ช่วยกำหนดค่ามาตรฐานใน Excel แต่ CSV มีเพียงผลลัพธ์สูตร HTML ต้องตรวจซ้ำเพื่อรับมือการคัดลอกแถว เขียนค่าทับสูตร เปลี่ยนหัวคอลัมน์ หรือลบข้อมูล ตรวจความสัมพันธ์เพิ่มเติมได้ แต่ไม่อาจพิสูจน์เจตนาของค่าที่ถูกชนิดและผิดความจริง เช่น กรอกวันที่ผิดวันแต่ยังเป็นวันที่ตามปฏิทิน

การล็อกชีตช่วยป้องกันความผิดพลาดจากการใช้งาน ไม่ถือเป็นหลักฐานความถูกต้องของไฟล์ และไม่ทดแทนการตรวจตอน Import เกณฑ์ข้างต้นเป็นเป้าหมายพัฒนา ต้องทดสอบกับแม่แบบจริงก่อนอ้างว่ารองรับครบ

**ไฟล์ในเครื่อง:** เปิด HTML ตรงได้โดยไม่ต้องเปิดตัวช่วย ส่วน `Open_Master_Schedule.cmd` ใช้ Local_File_Helper.ps1 เพื่ออ่าน path/เปิดเอกสารบน Windows อย่าเปิดตัวช่วยเป็นขั้นตอนประจำเมื่อแก้เอกสารหรือโปรแกรม รายละเอียดขอบเขต loopback/เส้นทางอยู่ใน AGENTS.md

## ตรวจให้ตรงกับสิ่งที่เปลี่ยน

แก้เอกสารอย่างเดียว: ตรวจลิงก์ ข้อมูลอ้างอิง และยืนยันว่า HTML ไม่เปลี่ยน

แก้โปรแกรมหรือข้อมูล: ตรวจ JSON/ไวยากรณ์ JavaScript และกรณีที่ได้รับผลกระทบ ชุดทดสอบที่มีอยู่ รันจากโฟลเดอร์โปรเจกต์ด้วย Node.js:

```powershell
node tests/DatabaseModel.test.cjs
node tests/CSVImport.test.cjs
node tests/Recovery.test.cjs
```

`DatabaseModel` ใช้ข้อมูลปัจจุบันและสร้างตัวอย่าง CSV/XLSX ใน `outputs/database/` ส่วน CSVImport/Recovery ใช้ fixture เก่า ไม่ใช่จำนวนงานล่าสุด หากรายการจริงเปลี่ยนให้ปรับความคาดหวังในชุดตรวจปัจจุบันตามคำขอที่ยืนยันแล้ว ห้ามคืนข้อมูลจริงเพื่อให้จำนวนตรงกับชุดทดสอบเก่า

ตรวจหน้าตา/การคลิกในเบราว์เซอร์เมื่อเปลี่ยน UI ตรวจ snapshot แล้วเปิดกลับเมื่อเปลี่ยนการบันทึกหรือโครงสร้าง แยกผลทดสอบจำลอง การตรวจเบราว์เซอร์ และการรัน Excel จริงออกจากกัน รายงานเฉพาะสิ่งที่ตรวจแล้ว ไม่ใช้ผลตรวจ VBA เดิมมายืนยันแนวทางใหม่

ปรับ README.md เมื่อรายการหรือพฤติกรรมสำคัญเปลี่ยน และปรับ AGENTS.md เฉพาะกติกาที่เปลี่ยนตามผู้ใช้ สรุปไฟล์ที่แก้ ผลตรวจ และข้อจำกัดที่ยังมี โดยไม่ commit หรือเผยแพร่หากผู้ใช้ยังไม่ได้ขอ
