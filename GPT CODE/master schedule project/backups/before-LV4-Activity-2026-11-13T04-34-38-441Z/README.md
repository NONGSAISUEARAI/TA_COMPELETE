# Master Schedule — Rev03

ปรับวันที่ 9 พฤศจิกายน 2026 เป็นฐานข้อมูล 3 ระดับตามที่ผู้ใช้ยืนยัน ยกเลิกชั้น PP17–PP20 ในโครงการหลัก โดยไฟล์ใช้งานคือ Master_Schedule.html ไม่ต้องติดตั้งแพ็กเกจ

## ข้อตกลงล่าสุด — 10 พฤศจิกายน 2026

สรุปการหารือเพิ่มเติมครั้งนี้เป็นภาษาไทย ปรับเฉพาะ README.md และ SKILL.md โปรแกรมและข้อมูลงานใน HTML ยังเป็น Rev03 เดิม

### รูปแบบไฟล์และขั้นตอนใช้งาน

- **JSON ใน HTML:** ข้อมูลหลัก รวมต้นไม้งาน รหัสงาน วันที่ และ metadata ไฟล์แนบ
- **CSV UTF-8:** รูปแบบนำเข้าที่ตกลงใช้ต่อไป รองรับภาษาไทย กรอกข้อมูลใน Excel แล้วเลือก Save As → CSV UTF-8 (Comma delimited) ไม่ใช้ VBA และไม่เปลี่ยนข้อสรุปเป็นนำเข้า XLSX โดยตรง
- **Excel `.xlsx`:** รายงานที่มีสี ฟอนต์ เส้นขอบ สูตร และ Gantt ตามแม่แบบ CSV เก็บเฉพาะค่า ไม่เก็บรูปแบบ หลายชีต หรือสูตร
- **ความเข้ากันได้:** ใช้ Excel 2016 เป็นฐาน รองรับถึง Excel 2024 ไม่พึ่ง Microsoft 365 และไม่ใช้ IFS, LET, UNIQUE, FILTER, XMATCH หรือฟังก์ชันใหม่ที่ Excel 2016 ไม่มี

### แม่แบบ Excel ที่ตกลงจะพัฒนา

เก็บ `Drawing_Template.xlsx` ใน GitHub ให้ HTML ใช้สำเนาแม่แบบ เติมข้อมูลจากชุดข้อมูลที่ใช้ส่งออก CSV ลงตำแหน่งที่กำหนด แล้วดาวน์โหลดเป็น XLSX ใหม่ แม่แบบต้นฉบับคงเดิมและไม่ใช้ VBA ไม่จำเป็นต้องสร้างไฟล์ CSV คั่นระหว่าง HTML กับแม่แบบทุกครั้ง หากต้องใช้แบบออฟไลน์ด้วย ต้องมีแม่แบบฝังไว้หรือเลือกไฟล์จากเครื่อง

**โครงสร้างแถวของ Template จะถูกล็อกทั้งหมด เพิ่มได้เฉพาะแนวนอน** ไม่เพิ่ม ลบ หรือย้ายแถวแนวตั้งในแม่แบบ แต่ละงานมีตำแหน่งและคู่ Plan/Actual ที่เตรียมไว้ คอลัมน์ข้อมูลหลักต้องไม่เลื่อน ส่วนขยายเพิ่มทางขวาตามมาตรฐานที่กำหนด หากจำนวนงานเปลี่ยน ให้จัดการรายการใน HTML และเตรียมแม่แบบรุ่นที่รองรับแทนการแทรกแถวในไฟล์เดิม

WBS เช่น `1.1.1` และ `1.1.2` ต้องเป็นสูตรในแม่แบบ ผูกกับโครงสร้างแถวคงที่และล็อกช่องสูตร คู่ Plan/Actual ของงานเดียวกันใช้เลขเดียวกัน ส่วน Task ID เป็นรหัสงานถาวรที่คงเดิม ไม่สร้างใหม่จากเลขแถว สูตร 365 และตัวอย่างตารางอ้างอิงที่เคยหารือยังไม่ใช่สูตรสุดท้าย ต้องวางสูตรให้ตรงแม่แบบจริงและตรวจความเข้ากันได้กับ 2016 ก่อน

### กติกาตรวจข้อมูลที่ต้องมีในแนวทางแม่แบบ

| สิ่งที่ตรวจ | สิ่งที่ต้องจับได้ |
| --- | --- |
| รหัส/เวอร์ชันแม่แบบ และชุดแถว | ใช้แม่แบบผิดรุ่น แถวขาด/เกิน/ย้าย หรือรหัสงานไม่ตรงกับชุดที่กำหนด |
| หัวคอลัมน์และตำแหน่ง | ลบ สลับ หรือซ้ำหัวคอลัมน์หลัก รวมถึงส่วนขยายแนวนอนที่ไม่อยู่ในมาตรฐาน |
| ข้อมูลหลัก 5 ช่องและชนิดข้อมูล | ช่องจำเป็นว่าง วันที่ผิด ปริมาณผิดชนิด วันจบก่อนวันเริ่ม |
| คู่ Plan/Actual | แต่ละ Task ID ต้องมีอย่างละหนึ่งแถว และคู่ Task ID + ประเภทแถวต้องไม่ซ้ำ |
| ชุด ID และความสัมพันธ์ | ID ของ Plan/Actual ต้องตรงกันทุกตัว รหัสแม่และข้อมูลโครงการ/Product/Description ของแต่ละคู่ต้องตรง |
| WBS | ตรวจค่าที่ได้กับโครงสร้างและตำแหน่งมาตรฐาน ไม่เชื่อค่าจาก CSV โดยลำพัง |
| ก่อนยืนยัน | แสดงรายการและค่าที่จะเปลี่ยน ระบุแถว/คอลัมน์/สาเหตุของข้อผิดพลาด และยังไม่แก้ข้อมูลจริงหากมีข้อผิดพลาด |

จำนวน Plan เท่ากับ Actual อย่างเดียวยังไม่พอ เช่น Plan มี A/B แต่ Actual มี A/C จำนวนเท่ากันแต่งานไม่ครบ คู่ของงานที่ยังไม่เริ่มจริงมีแถว Actual ได้โดยเว้นวันที่ว่าง ไม่สมมติวันที่เพื่อให้ผ่านการตรวจ

เมื่อบันทึก CSV จะเหลือเพียงผลลัพธ์ของสูตร ดังนั้นต้องตรวจซ้ำใน HTML แม้ช่องสูตรจะถูกล็อกไว้ การล็อกช่วยป้องกันการแก้โดยไม่ตั้งใจ แต่ไม่พิสูจน์ว่าไฟล์ถูกต้องทั้งหมด ข้อมูลที่ถูกชนิดแต่กรอกผิดความจริงยังต้องอาศัยผู้ใช้ตรวจ preview เช่น เลือกวันที่ผิดวันแต่เป็นวันที่ตามปฏิทิน

## เริ่มใช้งาน

1. เปิด [Master_Schedule.html](Master_Schedule.html) เพื่อดูตาราง เริ่มต้นเป็น Viewer
2. กด **ปลดล็อก Editor** ใส่รหัส `123123` เพื่อเพิ่มหรือแก้ข้อมูล
3. เพิ่มโครงการที่ LV1 → เพิ่ม Product ที่ LV2 → เพิ่ม Description ที่ LV3 แล้วกรอกวัน PLAN และ ACTUAL แยกกัน
4. กด **บันทึก HTML** เพื่อบันทึกลงไฟล์ หรือ **บันทึกสำเนา HTML** เพื่อเก็บโปรแกรมและข้อมูลเป็นไฟล์ใหม่ ฉบับร่าง Auto-save ในเบราว์เซอร์ไม่ใช่การบันทึกลงไฟล์ HTML

การดูและแก้ตารางไม่ต้องเปิดเซิร์ฟเวอร์ หากต้องการวางที่อยู่โฟลเดอร์แล้วอ่านรายการ/เปิดเอกสารผ่าน Windows ให้เปิด [Open_Master_Schedule.cmd](Open_Master_Schedule.cmd) ซึ่งเริ่มตัวช่วยเฉพาะเครื่อง

## เพิ่มและแก้ไข

เริ่มเป็น Viewer ปลดล็อก Editor ด้วย 123123 หมวดหลักใหม่กรอก PJ และ Project Works หัวข้อ LV2 กรอก Group Drawing และ Product งาน LV3 เลือก Product แล้วกรอก Description ข้อมูลโครงการและ Product ของงานรับจากหัวข้อแม่ แก้ชื่อ Product ครั้งเดียวแล้วข้อมูลในงานและไฟล์ส่งออกตามไปด้วย

โครงการฐานข้อมูลใช้ 3 ระดับ ไม่เพิ่มงานใต้ LV3 และไม่ย้ายโครงการ LV1 ไปซ้อนใต้หัวข้ออื่น หมวดเอกสารเก่ายังคงรูปแบบเดิม ย้ายลำดับด้วยคลิก WBS ต้นทาง/ปลายทางตามเดิม รักษา id ถาวรเมื่อแก้รายการ และคง id ของ C10 กับงานเดิมที่ตรงรายการใหม่

คง Dark Mode, SVG tree เส้น 1px, ยุบ–ขยาย, สี Gantt, PLAN/ACTUAL, วันทำงานจันทร์–เสาร์และการเว้นอาทิตย์ ปุ่ม Unhide 4 ช่องแสดง PJ/Project Works/Group Drawing/Product ซึ่งเริ่มซ่อน ป้ายจำนวนไฟล์อยู่ข้างชื่อหัวข้อฐานข้อมูล คลิกยุบ–ขยายชื่อไฟล์ที่เลือกได้

## ส่งออกและนำเข้า

Export Excel ส่งออกงานระดับสุดท้ายของโครงการฐานข้อมูลเท่านั้น แต่ละงานมี 2 แถว ข้อมูล PJ / Project Works / Group Drawing / Product / Description ครบทั้ง Plan และ Actual ไม่ใช้แถวหัวข้อหรือช่องว่างเพื่อสื่อความหมาย

| คอลัมน์ | ข้อมูล |
| --- | --- |
| A–E | PJ, Project Works, Group Drawing, Product, Description |
| F–P | ข้อมูลปัจจุบัน, Man, Unit, Quantity, Status, Action, Start, End, Approved, Remark, Duration ตามลำดับเดิม |
| Q | WBS สำหรับแสดงลำดับ |
| R | Plan / Actual |
| S | Node Type = Task |
| T | Task ID ถาวร |
| U | Project ID |
| V | Product ID |
| W เป็นต้นไป | ปฏิทินรายวันเมื่อเลือกส่งออกพร้อมปฏิทิน |

XLSX รักษาสีและรูปแบบต้นแบบ A:P พร้อมสูตรวันทำงานและ Gantt ที่ขยับตามวันที่ ซ่อน S:V ซึ่งเป็นรหัสอ้างอิง ห้ามแก้รหัสเหล่านี้เพื่อเปลี่ยนลำดับ ใช้ WBS ใน HTML จัดลำดับแทน

CSV เก็บเฉพาะข้อมูล ไม่มีสี ฟอนต์ หรือ format ของตาราง หากต้องการรูปแบบตาม Excel ต้นแบบให้เลือก Export Excel (.xlsx)

Import CSV อยู่ใน Editor รองรับ UTF-8 หัวตารางแถว 1 หรือ 4 ดาวน์โหลด CSV งานปัจจุบันไปกรอกใน Excel แล้วบันทึก CSV UTF-8 เพื่อนำกลับ ข้อมูลทั่วไปอ่านจากแถว Plan ส่วน Actual อ่านวันที่ L/M จับคู่งานจาก Task ID ก่อน จึงแก้ Description หรือย้ายลำดับได้ ถ้าไม่มี Task ID จะจับคู่ข้อมูล 5 ช่องที่ครบและไม่ซ้ำ

พฤติกรรม CSV ทั่วไปที่มีอยู่ใน Rev03: เพิ่มงานใหม่โดยเว้น Q และ T ในทั้งคู่ Plan/Actual หากเป็นโครงการหรือ Product ใหม่ให้เว้น U/V ด้วย ระบบสร้างหัวข้อที่ขาดจากข้อมูลครบ 5 ช่องโดยไม่คาดเดา ยังคงแสดงตัวอย่างก่อนยืนยัน เริ่มไม่ใช้ค่าว่างล้างข้อมูลเดิม การอัปเดตไม่เปลี่ยนสี ไฟล์แนบ ลำดับ หรือ % ของงานเดิม พฤติกรรมนี้ไม่ได้อนุญาตให้เพิ่มแถวใน Template แบบล็อกแถวที่ตกลงใหม่

ส่วนเก่าที่ยังอยู่: Export_MasterSchedule_CSV.bas และปุ่มดาวน์โหลด VBA ใน HTML เป็นโค้ดจากแนวทางเดิม ยังไม่ได้รัน macro รุ่นนี้ใน Excel จริง ผู้ใช้ยืนยันเลิกใช้ VBA แล้ว ให้บันทึก CSV UTF-8 จาก Excel โดยตรง ขั้นตอนถอดปุ่ม/โค้ดเก่าออกยังไม่ได้ทำในการอัปเดตเอกสารครั้งนี้

## ให้ Codex ทำต่อหรือย้ายเครื่อง

ใช้ [SKILL.md](SKILL.md) ในโฟลเดอร์นี้เป็นแนวทางทำงาน เช่นสั่งว่า “อ่าน SKILL.md กับ AGENTS.md แล้วเพิ่มรายการใน Master_Schedule.html โดยรักษาข้อมูลเดิม” ไฟล์ skill นี้เก็บไว้กับโปรเจกต์ ยังไม่ได้ติดตั้งเป็น skill ส่วนกลางของ Codex

หากย้ายเครื่อง ให้บันทึกข้อมูลลง HTML ล่าสุดก่อน แล้วคัดลอกทั้งโฟลเดอร์โปรเจกต์ เพื่อเก็บโปรแกรม เอกสารแนวทาง ตัวช่วย และสำเนากู้คืนไว้ด้วยกัน ที่อยู่โฟลเดอร์เอกสารยังอ้างเครื่องเดิม จึงต้องปรับ path และอ่านรายการใหม่บนเครื่องปลายทาง

ก่อนแก้โปรแกรมหรือข้อมูล ให้อ่าน JSON ใน `script#schedule-data` ของ HTML จริงและสำรองชื่อใหม่ก่อน ไม่ใช้ fixture หรือสำเนาเก่าทับข้อมูลปัจจุบัน ปรับเอกสารเมื่อรายการหรือพฤติกรรมเปลี่ยน รายละเอียดการตรวจและคำสั่งชุดทดสอบอยู่ใน SKILL.md
