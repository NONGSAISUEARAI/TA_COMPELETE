# ตรวจและแก้ FO กับ test.dwg

ทดสอบวันที่ 3 พฤศจิกายน 2026 บน AutoCAD 2026 Core Console ด้วยสำเนาจาก `C:/TA/PPLINE CKST/C1-C2_Finishes-Reflected Ceiling Plan/PP17/CAD/test.dwg`

## ข้อผิดพลาดที่พบ

เลือก Pline ปิดทั้ง 14 เส้นแล้ว FO รุ่น 1.6 ยกเลิกพร้อมข้อความ:

```text
Some selected edges lie outside the outline. Check the open source geometry.
```

เส้นต้นทางปิดอยู่แล้ว สาเหตุอยู่ที่ `TFO:OuterLoops` ใช้เพียงจุดแรกของวงขอบตัดสินว่าอยู่ภายในวงใหญ่กว่า รอยต่อระหว่างแผงในไฟล์นี้คลาดกันเพียงเศษเล็กมากของหน่วยแบบ ทำให้จุดแรกฝั่งซ้ายเข้าไปอยู่ฝั่งเพื่อนบ้านเล็กน้อย โปรแกรมจึงทิ้งขอบของแผงด้านซ้าย 2 ชิ้นเหมือนเป็นวงขอบด้านใน ทั้งที่พื้นที่เกือบทั้งหมดของแผงอยู่ข้างนอก

เมื่อขอบหาย ขั้น Overall พยายามสร้างรูปเชื่อมจากเส้นที่เหลือ บางรูปบางมากจน AutoCAD ปฏิเสธ REGION และขั้นตรวจท้ายสุดพบเส้นแผงต้นฉบับอยู่นอกขอบ จึงยกเลิกโดยไม่มีผลลัพธ์ค้าง

## การแก้

รุ่น 1.7 เปลี่ยน `TFO:OuterLoops` ให้ตรวจทุกช่วงขอบของวงนั้นด้วย `TFO:EdgeCovered` ก่อนตัดสินว่าเป็นวงขอบด้านใน วงที่เพียงแตะหรือเกือบทับขอบเพื่อนบ้านจึงไม่ถูกตัดออกจากการคำนวณ

คงค่า preset เดิมของผู้ใช้ รวมถึง `tolerance_fo_ = 0.01`, `factor_area_ = 0.000001`, รายการ exception และชื่อบล็อก Area/Length ไม่ใช้การเพิ่ม tolerance หรือปิดขั้นตรวจความครบของขอบเพื่อกลบปัญหา

## ผลหลังแก้

รันคำสั่ง `c:FO` จริงโดยตั้ง 14 Pline เป็นชุดเลือกไว้ก่อนในสำเนาแบบ:

- Outline ปิด 1 เส้น มี 9 จุดยอด เก็บขั้นเว้าด้านล่างซ้าย
- พื้นที่ภายในขอบ 9.18687046 ตร.ม. แสดง Attribute `AREA=9.19`
- บล็อก `facade_1_INFO` 1 ตัว มี `AREA`, `MAT`, `STATION`, `FLOOR`; ไม่สร้าง LENGTH
- ข้อมูล DXF ของชิ้นงานต้นทางทั้ง 14 เส้นก่อนและหลังรันตรงกัน
- ชุดทดสอบรวม 93 กรณี ผ่านทั้งหมด รวมรูปทรงที่ทำให้เกิดข้อผิดพลาด การกลับลำดับเลือก ช่องด้านในที่ต้องถูกกรองจริง ขอบเว้า บล็อกซ้อน Attribute และ UNDO
